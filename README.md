
# PDTracker

### Android Application | IoT | Software Quality Assurance

PDTracker is a mobile application project focused on monitoring symptoms associated with Parkinson's disease, including functionality related to sensor data and fall detection.

The project involved Android development and IoT-related functionality, with software testing playing an important role in validating application behaviour and monitoring workflows.

This was a collaborative project. My contribution focused on software quality assurance, particularly the preparation of test documentation and the validation of application functionality.

## Project Overview

PDTracker was designed to explore how mobile and sensor-based technologies could support the monitoring of symptoms associated with Parkinson's disease.

The application involved interactions between mobile functionality, sensor information, and alert-related behaviour.

From a QA perspective, the project presented important testing challenges because the expected behaviour depended not only on user interactions but also on data received from sensors and the application's response to that data.

## Project Objectives

The project's main objectives included:

- Develop a mobile solution for Parkinson's symptom monitoring.
- Explore the use of sensor-based information.
- Support functionality related to fall detection.
- Process relevant information within the Android application.
- Validate application behaviour under different conditions.
- Test the relationship between sensor data and application responses.
- Identify functional issues before project delivery.
- Document testing activities and results.

## Testing Scope

### Functional Testing

Functional testing focused on verifying that the application behaved according to its intended requirements.

Relevant testing areas included:

- Application functionality
- Sensor-related data handling
- Fall-detection behaviour
- Alert-related responses
- Expected application reactions to relevant inputs

### Sensor Data Validation

Testing sensor-based functionality requires considering the relationship between input data and the application's resulting behaviour.

The goal was to identify inconsistencies and verify that the application handled relevant sensor information as expected.

### Fall Detection and Alert Logic

Fall detection and alerts were important areas because they involved application responses to specific conditions.

QA validation focused on whether these workflows behaved consistently with the project's intended logic.

### Test Documentation

A significant part of my contribution was documenting the testing work.

This included organising the relevant scenarios, expected behaviour, and testing observations in a way that supported review and validation.

## Testing Process

My QA activities followed a structured process:

1. Understand the relevant project requirements.
2. Identify application features requiring validation.
3. Define testing scenarios.
4. Document expected behaviour.
5. Prepare test cases.
6. Execute or support the relevant validation activities.
7. Compare actual behaviour with expected results.
8. Record observations and identified issues.
9. Review the testing outcomes.
10. Maintain the test documentation as evidence of the QA work.
